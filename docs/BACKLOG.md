## 優先級

| 級別 | 意義 |
|---|---|
| **P0** | 沒有它就不算完成專題 |
| **P1** | 有它會明顯加分，時間夠就做 |
| **P2** | 加分項，有餘力再說 |
| **P3** | 先記著，本期不做 |

## 完成定義（Definition of Done）

一項工作要算完成，必須同時滿足：

- [ ] 程式可跑，且用真實操作驗證過（不是只看程式碼）
- [ ] 資料庫變更已寫進 `schema.sql`
- [ ] 有對應的 API 或畫面
- [ ] 已 commit，並開 PR
- [ ] 報告／README 有同步更新

## Sprint 1｜地基與既有功能整理

**目標**：把 v2 的程式重構成深模組，補上 Git 與測試，作為後續功能的基礎。

| ID | 工作 | 為什麼 | 估時 | 狀態 |
|---|---|---|---|---|
| S1-1 | Git repo + `.gitignore` + 首次 commit | 目前完全沒有版控 | 0.5h | ✅ |
| S1-2 | 推上 GitHub、設 PR 流程 | 組員要能協作 | 0.5h | ⬜ |
| S1-3 | 拆出 `domain/trading.js`（`placeOrder`） | 交易邏輯最深，最該獨立 | 2h | ⬜ |
| S1-4 | 拆出 `domain/portfolio.js`（`snapshot`） | 資產計算是另一條主線 | 1h | ⬜ |
| S1-5 | 拆出 `domain/market.js`（`quotes`） | 行情查詢獨立 | 0.5h | ⬜ |
| S1-6 | SQL 集中到 `db/queries.js` | 改 schema 時只改一處 | 1h | ⬜ |
| S1-7 | 錯誤碼統一（`INSUFFICIENT_CASH` 等） | 前端才能穩定處理 | 1h | ⬜ |
| S1-8 | 整合測試：買、賣、餘額不足、持股不足 | 重構後要有安全網 | 2h | ⬜ |
| S1-9 | CI：PR 時自動跑語法檢查與測試 | 防止壞掉的程式進 main | 1h | ⬜ |

**Sprint 1 驗收**：重構後行為與現在完全相同，測試全綠。

## Sprint 2｜市場會動（下一個要做的）

**目標**：股價每天變動，有歷史資料與走勢圖。這是 demo 最有感的一段。

| ID | 工作 | 為什麼 | 估時 | 依賴 |
|---|---|---|---|---|
| S2-1 | 新增 `price_history` 表 + 索引 | 時間序列的核心 | 1h | S1-6 |
| S2-2 | `market.tick(db, date)`：產生當日價格 | 模擬漲跌 | 2h | S2-1 |
| S2-3 | `GET /api/history?symbol=&days=` | 前端畫圖用 | 1h | S2-1 |
| S2-4 | 首頁加上折線圖（SVG，不引外部套件） | demo 賣點 | 3h | S2-3 |
| S2-5 | 種子 30 天歷史資料 | 一打開就有圖 | 1h | S2-1 |
| S2-6 | 每日自動 tick（Cron Trigger） | 顯示系統會自己動 | 1h | S2-2 |
| S2-7 | 交易頁顯示「今日漲跌」 | 讓畫面有生命 | 1h | S2-2 |

**Sprint 2 驗收**：打開首頁看到 30 天走勢圖；按一下「模擬一天」，價格與圖表都更新。

> ⚠️ 這一版要先做 **S1-3 重構**，否則 `index.js` 會膨脹到沒人能改。

## 建議的執行順序

```
S1-2（推 GitHub）
  → S1-3 ~ S1-6（重構）
  → S1-8（測試）
  → S2-1 ~ S2-7（市場會動）
  → S3（多人）
  → S4（交付）
```

**理由**：先把程式變得好改，再加功能。反過來做的話，Sprint 2 會把 `index.js` 撐爆。
